## 2. A* 的状态、更新与停止条件

`lab2/pathfinding.py` 以格子坐标作为状态。对当前目标 `t`：

\[
g(n)=\text{目前已知的起点到 }n\text{ 的最小代价},\qquad
h(n)=\text{从 }n\text{ 到 }t\text{ 的剩余代价下界},\qquad
f(n)=g(n)+h(n).
\]

优先队列首先按 `f` 选择节点。`best_g` 保存当前最优已知代价，`parent` 保存前驱。对边 `u→v`，候选代价为 `g(u)+w(v)`；只有严格变小时才更新并入堆。这个严格不等式也避免零权环造成无穷次等价入队。A* 将已经付出的代价与剩余代价估计结合，可采纳启发函数提供最优性所需的下界；基础概念参考 [Berkeley CS188：Informed Search](https://inst.eecs.berkeley.edu/~cs188/textbook/search/informed.html)。

本实现使用延迟删除：改进一个格子的代价时直接加入新堆项，旧堆项留待弹出；若弹出项的 `g` 已不等于 `best_g`，将其记为 `stale_pops` 并跳过。目标在有效出堆时结束搜索，不能在第一次发现目标时结束。

`closed` 不等于永远禁止再访问。如果某个已展开节点出现更小的 `g`，代码会移出 `closed` 并重新打开，即 `reopened`。在启发函数可采纳但不一致时，这一步防止较差的第一次访问锁死最优路径。可采纳性不能仅靠检查返回值非负来证明；自定义启发函数需要调用者提供数学保证。内置检查只负责拒绝非法数值及 `h(goal)≠0`。

启发函数一致表示每条边都满足 `h(u)≤w(v)+h(v)`。对于内置的安全一致启发函数，节点不需要反复展开；对于外部传入的不一致函数，重新打开可能增加开销。`heuristic="zero"` 使 A* 退化为 Dijkstra，是加权问题的正确性与性能基线。

### 2.1 题二零代价终点的安全启发函数

原始曼哈顿距离为

\[
M(n,t)=|r_n-r_t|+|c_n-c_t|.
\]

题一中每条边代价为 1，因此 `h=M` 是安全下界。题二存在 `E=0`，例如与 E 相邻的格子，真实剩余代价是 0，而曼哈顿距离是 1，直接使用 `M` 已经高估。这里必须区分“违反常用最优性充分条件”和“算法必然返回次优解”：后者不能仅由前者推出，原题的特殊权重条件实际上还能给出单独的最优性证明。

当前 `goal_aware_heuristic` 使用以下针对进入格子代价模型的推导。令 `w(t)` 是目标格权重，`m` 是所有非目标可走格的最小权重；没有非目标格时取 `m=0`。定义

\[
h(t)=0,\qquad
h(n)=(M(n,t)-1)m+w(t),\quad n\ne t.
\]

**可采纳性。** 考察首次到达目标的任一路径，设它包含 L 条边。四连通意味着 `L≥M(n,t)`。最后一条边必收取 `w(t)`，其余 `L−1` 条边都进入非目标格，每条至少收取 m。因此路径代价至少为 `(L−1)m+w(t)`，也就至少为 `(M−1)m+w(t)`。起点原地不收费与此推导一致，因为只累计沿边进入格子的费用。

**一致性。** 对相邻的非目标格 u、v，曼哈顿距离之差不超过 1，所以 `h(u)−h(v)≤m≤w(v)`。若 v 就是目标，则 `M(u,t)=1`，于是 `h(u)=w(t)=w(t)+h(t)`。若 u 是目标，则 `h(u)=0≤w(v)+h(v)`。所有边都满足一致性。

题二样例非目标格的最小权重为 1、终点权重为 0，因此该式为 `h=max(M−1,0)`。若扩展数据的内部也有零权格，则 `m=0`，非目标启发值退化为 `w(t)`；若终点也为 0，则退化为 0。它会变弱但仍然安全。不能在存在内部零权格时继续假设每一步至少花费 1。

**原题限定条件下对原始 M 的进一步辨析。** 只允许终点权重为 0、其他格权重都至少为 1 时，非目标节点的原始曼哈顿值恰好比安全的 `M−1` 多 1。设最优路径代价为 C*。在最优路径尚未全部展开时，路径上仍有一个已发现的前沿节点，其原始 `f=g+M≤C*+1`。任何以次优 g 到达的目标前驱 p 则满足 `M(p,t)=1`；最后进入目标不收费，所以其 `g(p)>C*`，原始 `f(p)=g(p)+1>C*+1`。这样的次优前驱不可能先于最优路径前沿被选中。因此首次展开能生成目标的前驱已经获得最优代价，随后有效出堆的目标也最优。这是利用原题额外结构得到的证明，并没有使原始 M 变成可采纳函数。

本实验默认仍采用有明确一致性证明且能兼容内部零权的目标修正公式。为了检验更一般情形，另设**含内部零权格的扩展反例**：网格 `[['S',3,'E'],[1,0,1]]`，起点 `(0,0)`、目标 `(0,2)`，E 进入代价为 0。原始 M 在 `fifo` 和 `larger_g` 下均先走上方代价 3 的路线；安全启发与 Dijkstra 返回下方代价 `1+0+1+0=2` 的路线。这个反例改变了原题“非终点至少为 1”的条件，必须标为扩展测试，不能伪称给定样例已经出现了次优解。

### 2.2 平局策略与复杂度

`fifo` 在 f 相同时按入堆顺序访问；`larger_g` 在 f 相同时先选较大的 g，再按入堆顺序决定。固定 f 时，较大 g 等价于较小 h。它只调整相同优先级内部的次序，不改变最优解目标。零代价动作产生大面积相同 f 的区域时，平局规则可能显著影响展开量，这也是开展对照实验的依据。[Asai 与 Fukunaga 的 AAAI 2016 论文](https://ojs.aaai.org/index.php/AAAI/article/view/10071)专门研究了该问题；本实验比较的是确定性的 FIFO 与较大 g 优先，没有复现其全部随机化方法，也不把论文性能直接当作本实验结果。

设网格共有 N 个格子，其中 V 个可走，边数 E≤4V。安全一致启发函数下，二叉堆搜索最坏为 `O((V+E) log V)`，在四连通网格上可写为 `O(V log V)`，搜索工作空间为 `O(V)`。当前默认启发函数构造还需要一次 `O(N)` 全图扫描，所以单次调用总时间界应包含该项。题一虽是单位代价迷宫，使用队列的 BFS 可达 `O(V+E)`，但本题按要求实现 A*，不应将 BFS 的线性时间直接写成这个堆实现的时间界。

这些界以一致性和本实验稀疏网格为前提。允许重新打开的不一致启发函数可能多次展开同一状态，不能无条件沿用“每格最多展开一次”。开启完整轨迹还会增加记录空间与时间，性能测试应关闭轨迹。

## 3. 有向 ALT 地标启发函数拓展

ALT 将 A*、地标和三角不等式结合，适用于同一图上反复进行最短路查询。其来源是 [Goldberg 与 Harrelson，Computing the Shortest Path: A* Search Meets Graph Theory，SODA 2005，第 6 节](https://www.microsoft.com/en-us/research/wp-content/uploads/2005/01/soda05.pdf)。本实验实现的是单向 A* 的地标下界，不是该论文全部双向搜索和地标选择方法的复现。

地图几何邻接虽然双向存在，但进入格子收费使 `c(u,v)=w(v)`、`c(v,u)=w(u)`，边权未必对称。因此 `LandmarkIndex` 为每个地标 L 分别保存：

\[
\mathrm{forward}_L(v)=d(L,v),\qquad
\mathrm{reverse}_L(v)=d(v,L).
\]

前者在原图上从 L 运行 Dijkstra。后者在反图上从 L 运行 Dijkstra；当反图从当前格 v 走向邻格 u 时，它代表原图的 `u→v`，代价必须是 `w(v)`，即代码的 `grid.cost(current)`。若错误地仍收取 `w(u)`，得到的就不是原图各点到 L 的距离。

对当前节点 n 和目标 t，最短距离的三角不等式给出

\[
d(L,t)\le d(L,n)+d(n,t),\qquad
d(n,L)\le d(n,t)+d(t,L).
\]

移项得到两个剩余距离下界，组合后的实际启发函数为

\[
h_{ALT}(n)=\max\left(0,\ h_{goal}(n),\ \max_L[d(L,t)-d(L,n)],\ \max_L[d(n,L)-d(t,L)]\right).
\]

这里只在相减的两个距离都存在时使用该项，避免不可达距离相减。当前网格每条几何边都有反向边，因此一个连通分量内部双向可达；这一处理不应未经论证就照搬到任意单向可达网络。

每个地标项由三角不等式得到下界，并满足边一致性；常数 0 与安全网格下界也一致。对这些函数取最大值仍然可采纳且一致：若每个 `h_i(u)≤c(u,v)+h_i(v)`，则取最大值后有 `max_i h_i(u)≤c(u,v)+max_i h_i(v)`。因此 ALT 可以增强下界，保持与 Dijkstra 相同的最优代价。下界更强不等于每次查询必然更快，计算 K 个地标项本身也有开销。

K 个地标需要约 2K 次 Dijkstra，预处理时间为 `O(K(V+E) log V)`，距离表空间为 `O(KV)`，单个节点的地标估计为 `O(K)`。在查询数为 Q 时，应同时记录：

\[
T_{\mathrm{total}}=T_{\mathrm{preprocess}}+\sum_{q=1}^{Q}T_q,\qquad
\overline T_{\mathrm{amortized}}=T_{\mathrm{total}}/Q.
\]

查询耗时还应包含 `index.heuristic(goal)` 在外部构造目标启发函数的时间。当前这个构造会准备安全下界并扫描网格。`astar.stats.elapsed_ns` 无法自动包含进入 `astar` 前完成的工作，因此 ALT 批次应使用外层计时。不能只展示查询阶段变快，忽略地标预处理、表规模和小查询量下可能不划算的结果。`table_entries` 是距离标量数量，不是实际内存字节数。

## 4. Minimax、Alpha-beta 与题三复核

以 A/MAX 的效用为统一评价尺度，Minimax 在 MAX 层取子节点最大值，在 MIN 层取最小值，叶节点返回指定评价。其正确性可对剩余深度归纳：叶值正确；如果所有子状态均给出该深度下的正确值，则当前行动者选择最有利的那个值就是本层值。这个结论针对指定深度和评价规则；提前截断的评价不自动等于完整游戏终局结果。[Berkeley CS188：Minimax](https://inst.eecs.berkeley.edu/~cs188/textbook/games/minimax.html)给出了交替选择、剪枝和深度受限评价的基础说明。

Alpha-beta 传递祖先决策允许的窗口 `[α,β]`。MAX 节点更新 α，MIN 节点更新 β。当 `α≥β` 时，后续兄弟不能改善祖先已经能获得的选择，可直接停止访问。根使用 `[-∞,+∞]`，因此返回与同深度、同评价函数的 Minimax 相同的精确根值。窗口之外的内部返回值可能只是上界或下界，不必是该子树的精确值。关于窗口内精确、窗口外仅界的含义，参考 [Yale CPSC 474 讲义，第 5.2 节](https://zoo.cs.yale.edu/classes/cs474/f2022/CPSC_474.pdf)。

题三三个底层 MAX 值为 `max(3,5)=5`、`max(6,9)=9`、`max(1,2)=2`，其中 `[6,9]` 在 JSON 树的两处分别出现。因此两个 MIN 值为 `min(5,9)=5`、`min(9,2)=2`，根为 `max(5,2)=5`。

PDF Python 示意可能复用同一个 `[6,9]` 节点对象，JSON 则复制了两份。题三基线按树的访问次数统计，即使两个父节点引用同一个 Python 对象，也分别递归；不能用对象身份去重悄悄改变访问量。默认不启用缓存。完整 Minimax 访问 15 个节点、评价 8 个叶节点；从左到右的 Alpha-beta 跳过左侧第二个 MAX 的叶 9，访问 14 个节点、评价 7 个叶节点。到达某内部节点最后一个孩子后才满足窗口截止条件，已经没有兄弟可跳过，不计作有效剪枝。

对最大分支数 b、深度 H，完整 Minimax 搜索节点量最坏为 `O(b^H)`；Alpha-beta 的最坏情况相同，理想排序下可接近 `O(b^(H/2))`，不能将理想情况写成所有输入的保证。深度优先控制栈为 `O(H)`；本实现各层保留候选列表需要 `O(bH)`，还逐层保留访问路径元组，最坏另需 `O(H²)`，不能把代码的全部辅助空间简单写成 `O(H)`。已有输入树、游戏状态中的剩余集合、缓存和完整轨迹还应分别计算。题四有 n 个宝藏、逐步减少分支时，更准确的未剪枝节点量是 `Σ[k=0..min(H,n)] n!/(n−k)!`，而不是始终把每层分支都视为 n。该式描述搜索节点量；实际运行时间还包括状态构造、排序和缓存键构造等每节点开销。

## 5. 题四状态转换、深度与动作比较

`GameState` 包含双方位置、剩余宝藏、双方累计得分和轮到的玩家。A 先手。当前玩家从位置 p 领取目标 Ti 的即时收益为

\[
\mathrm{gain}(p,T_i)=\mathrm{value}(T_i)-d(p,T_i),\qquad U=\mathrm{ScoreA}-\mathrm{ScoreB}.
\]

A 行动时给 `score_a` 加上 gain，B 行动时给 `score_b` 加上 gain，再删除这个目标、更新行动者位置并换手。负 gain 仍是合法收益，不能擅自跳过不赚钱的目标，否则改变了规则。不可达目标用距离 `None` 表示并排除；扩展约定为当前玩家没有可达目标时直接以当前 U 终局。这是对未定义特殊情况的明确处理，给定样例不存在这一情况。

深度 H 以单个玩家的一次行动为一个 ply。H=2 表示 A 行动后 B 行动，H=4 表示 A、B 各两次；不能将 H=2 理解为双方各走两次。深度为 0 或宝藏已取完时评价当前 U。较浅搜索选择 T2、完整四步选择 T3，体现当前收益与后续位置、剩余目标之间的取舍，不能仅靠第一步即时收益解释整局最优性。

`natural` 按输入宝藏顺序，`reverse` 按其逆序，`greedy` 按当前玩家即时收益降序并稳定处理平局。A、B 均先访问自己即时收益较高的目标；这是搜索顺序，不限制后续最优决策，也没有偷用完整 Minimax 真值排序。切换顺序可能改变剪枝量，同值最优动作也可能随访问顺序改变；精确效用应保持不变。

选首步时仅在严格更优时替换已有候选。例如后访问子树返回一个与当前最优相同的上界，不足以证明它真正等值最优。如果为了“同值选择某个名称”无条件覆盖首步，可能返回实际较差的动作。当前实现保持第一个确证最佳的动作。

要在报告中比较“每一个根动作的精确得分”，应固定该动作产生子状态，然后以剩余 `H−1` 深度、完整窗口分别重新求解。`solve_treasure` 返回的已经是包含子状态累计得分的完整 U，不要再加一次第一步收益。普通单次 Alpha-beta 中各根分支的中间返回值不都精确，不能直接当作根动作价值表。

## 6. 未来效用规范化置换表

不同领取顺序可能到达相同的双方位置、剩余宝藏和当前玩家，造成重复子问题。置换表缓存已经搜索的状态与深度，基础思路参考 [Yale CPSC 474 讲义，第 5.1.2 节](https://zoo.cs.yale.edu/classes/cs474/f2022/CPSC_474.pdf)。本实现进一步针对本题加法收益模型，缓存未来效用增量，而不是直接缓存包含历史分数的总效用。

令 `F(s,h)` 表示从状态 s 再搜索 h 步能够取得的未来效用增量，当前累计效用为 `U(s)`。则

\[
V(s,h)=U(s)+F(s,h).
\]

若动作 a 到达 s′，令 `Δ=U(s′)−U(s)`。A 行动的 Δ 是 gain，B 行动的 Δ 是 `−gain`。递推为

\[
F(s,h)=\begin{cases}
0,&h=0\text{ 或已终止};\\
\max_a\{\Delta+F(s',h-1)\},&\text{轮到 A};\\
\min_a\{\Delta+F(s',h-1)\},&\text{轮到 B}.
\end{cases}
\]

在当前规则中，历史分数不影响合法动作、移动距离或之后的收益，所以 F 与累计分数无关。缓存键为 `(剩余深度, A位置, B位置, 剩余宝藏集合的规范顺序, 当前玩家)`。双方位置不能省略，因为下次移动代价取决于它们；剩余深度不能省略，因为截断评价随深度改变；玩家不能省略，因为 MAX/MIN 不同。游戏对象中的地图距离与价值在一次搜索中固定，表不跨不同游戏或不同求解调用复用。

父节点比较的是 `Δ+F(child)`。因此父窗口 `[α,β]` 传入子递归前，必须平移为 `[α−Δ,β−Δ]`，子返回值再加 Δ。只从缓存值中减掉累计 U 而不平移窗口，会破坏剪枝判定。最外层搜索结束后仅加回初始状态的 U 一次。

Alpha-beta 缓存条目包含数值、首步与标志：

| 标志 | 数学含义 | 读取时的处理 |
| --- | --- | --- |
| `EXACT` | 未来效用恰为 x | 可直接返回 |
| `LOWER` | 真实未来效用至少为 x | 用 x 提高 α |
| `UPPER` | 真实未来效用至多为 x | 用 x 降低 β |

若读取界后 `α≥β`，当前窗口下已无须继续搜索；这是缓存界命中，不单列为跳过兄弟的 `cutoffs`。新结果相对进入该次调用时的原始窗口判断标志：返回值不大于原 α 时存 UPPER，不小于原 β 时存 LOWER，否则存 EXACT；终止节点的未来增量 0 总是精确值。完整 Minimax 的缓存条目均为 EXACT。

每次 `solve_treasure` 都创建新的表，保证重复计时使用冷缓存。缓存减少递归不保证减少墙钟时间，小实例中的建键和字典操作可能抵消收益，必须同时报告节点量、命中量和时间。扩展到大量宝藏时，当前未设置容量上限的表可能占据较多内存；这属于实现适用范围，不能只描述加速效果。

## 7. 搜索数据的定义与公平比较

两个模块都使用 `perf_counter_ns`，但其计时范围不同，报告必须明确：

| 模块或步骤 | 计时范围 |
| --- | --- |
| A* `elapsed_ns` | 输入检查、启发准备、搜索、路径还原 |
| A* `preparation_ns` | 上一项中输入检查与启发准备的子集，不能再次相加 |
| 博弈 `elapsed_ns` | 完成输入验证后的递归搜索，含本次查询的缓存操作 |
| ALT `preprocessing_ns` | 建立正向、反向地标距离表 |
| ALT 外层批次计时 | 还需包括每个目标启发函数的构造与全部查询 |

同一模块内比较变体时采用相同验证、计时和轨迹开关。不要直接将不同问题、不同计时范围的数值解释成算法快慢。微小样例单次耗时受解释器、调度和计时开销影响，应进行多次重复，保存原始数据并报告中位数与离散程度；节点数为确定性补充，不能用一次特别快的运行代替整体结论。

寻路计数口径：

| 字段 | 含义 |
| --- | --- |
| `popped` | 有效出堆次数，包含目标；可因重新打开而重复计数 |
| `expanded` | 实际枚举邻居的次数，不包含直接返回的目标 |
| `generated` | 枚举合法邻居的总次数，包含重复状态 |
| `discovered` | 曾发现的不同格子数 |
| `reopened` | 已关闭格因更小 g 而重新打开的次数 |
| `stale_pops` | 延迟删除的过期堆项数 |
| `max_frontier` | 实际堆项数峰值，包含未弹出的过期项 |

博弈计数口径：

| 字段 | 含义 |
| --- | --- |
| `visited` | 递归调用次数，包含缓存命中的调用 |
| `expanded` | 实际展开子动作的内部节点数 |
| `leaves` | 实际执行终止/截断评价的次数，不含直接缓存返回 |
| `cutoffs` | 确实跳过至少一个未访问兄弟时的截断次数 |
| `pruned_branches` | 直接跳过的兄弟分支数，不是其所有后代节点数 |
| `cache_hits` | 查询到表条目的次数，包含只能收紧窗口的界命中 |
| `cache_stores` | 写入缓存的次数，包含覆盖，不等于最终表条目数 |

`pruned_branches=3` 不能被写成“剪掉 3 个节点”，因为每个分支可能含很多后代。如果需要表达相对基线的总访问减少率，可在相同输入和深度下另算 `1−visited_优化/visited_Minimax`，并明确这是总访问节省，可能同时来自剪枝和缓存。

## 8. 与评分点对应的报告证据

| 评分方向 | 本实现提供的依据 | 报告需要补充的分析 |
| --- | --- | --- |
| 代码正确性与规范（30 分） | 四题接口、输入验证、中文说明、给定样例、独立基准差分测试 | 解释模型与关键边界；选择代表性测试展示，避免只列通过数量 |
| 算法性能（10 分） | 节点数、重复计时、不同深度、排序与缓存开关 | 同输入公平比较；解释节点减少但时间不降的情况 |
| 实验报告（50 分） | 本文的状态定义、公式推导、计数口径与来源 | 填入真实数据和图表，讨论差异、局限与结论，不将本文当完整报告 |
| 创新拓展（10 分） | 零权目标安全启发、平局规则对照、有向 ALT 与摊销、规范化安全置换表 | 说明借鉴来源、本题适配、正确性依据及消融结果，报告失败或收益有限的条件 |

推荐的消融方式是一次只改变一个因素：Dijkstra→安全 A*→相同启发下改变平局；单独比较 ALT 查询阶段和含预处理总成本；Minimax→Alpha-beta→改变动作顺序→加置换表。最终结论应建立在保留最优值且通过独立验证的前提上，说明优化在哪些地图、深度或宝藏规模下有效，而不是只挑最有利的一次结果。
